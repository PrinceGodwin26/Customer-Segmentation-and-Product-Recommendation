# Customer Segmentation & Product Recommendation

A machine learning application that segments e-commerce customers by purchasing
behavior and generates personalized product recommendations for each segment.
Originally developed as a Jupyter notebook, it has been restructured into a
production-style service with a REST API and an interactive dashboard.

## Overview

The system processes raw transactional data (invoices, products, customers)
through a full ML pipeline:

1. **Data Cleaning** — removes missing values, duplicates, cancelled-order
   noise, invalid stock codes, and zero-price records.
2. **Feature Engineering** — derives RFM (Recency, Frequency, Monetary)
   metrics plus behavioral, geographic, cancellation, and seasonality
   features for every customer.
3. **Outlier Detection** — flags atypical customers with Isolation Forest and
   excludes them from clustering.
4. **Dimensionality Reduction** — compresses the feature space with PCA.
5. **Clustering** — groups customers into segments with K-Means.
6. **Recommendation Generation** — for each customer, recommends best-selling
   products from their segment that they haven't purchased yet.

The pipeline is exposed through a **FastAPI** service and visualized in a
**Streamlit** dashboard.

## Architecture

```
┌─────────────────┐      ┌──────────────────┐      ┌────────────────────┐
│  Raw CSV data    │ ───▶ │   app/ pipeline   │ ───▶ │  In-memory results  │
│ (transactions)   │      │  clean → engineer │      │  (customers, PCA,   │
└─────────────────┘      │  → cluster → rec.  │      │  clusters, recs)    │
                          └──────────────────┘      └──────────┬──────────┘
                                                                │
                          ┌──────────────────┐      served by  │
                          │  Streamlit        │ ◀── HTTP ───────┤
                          │  dashboard        │                │
                          └──────────────────┘      ┌──────────▼──────────┐
                                                     │   FastAPI service   │
                                                     │   (api/main.py)     │
                                                     └─────────────────────┘
```

The pipeline logic (`app/`) is shared code — the API calls it to run the
pipeline and cache results in memory; the dashboard never touches the data
directly, it only calls the API.

## Prerequisites

- Python 3.10+

## Installation

```bash
git clone <your-repo-url>
cd customer-segmentation-and-product-recommendation

python3 -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate

pip install -r requirements.txt
```

## Usage

Start the API (Terminal 1):

```bash
source .venv/bin/activate
uvicorn api.main:app --reload --port 8000
```

Start the dashboard (Terminal 2):

```bash
source .venv/bin/activate
streamlit run dashboard/app.py
```

Open the dashboard at `http://localhost:8501`. It talks to the API over
HTTP — configure the API's base URL from the dashboard sidebar, or via the
`API_BASE_URL` environment variable (defaults to `http://localhost:8000`).

The API runs the pipeline automatically on startup, using whatever dataset is
configured (see [Dataset](#dataset) below). Interactive API docs are
available at `http://localhost:8000/docs`.

## Dataset

The pipeline expects a CSV with these columns:

| Column | Type | Description |
| --- | --- | --- |
| `InvoiceNo` | string | Invoice ID. Prefixed with `C` for cancelled orders. |
| `StockCode` | string | Product/item code. |
| `Description` | string | Product name. |
| `Quantity` | int | Units purchased (negative for cancellations). |
| `InvoiceDate` | datetime | Date and time of the transaction. |
| `UnitPrice` | float | Price per unit. |
| `CustomerID` | numeric | Unique customer identifier. |
| `Country` | string | Customer's country. |

This repository ships with `data/placeholder_data.csv` — a synthetic dataset
generated by `scripts/generate_placeholder_data.py` with the same schema and
realistic data-quality issues (missing values, duplicates, cancellations,
anomalous codes), so the full pipeline runs end-to-end out of the box.

**To use your own data**, either:

1. Set the `DATA_PATH` environment variable before starting the API:
   ```bash
   export DATA_PATH=/path/to/your_data.csv
   uvicorn api.main:app --reload --port 8000
   ```
2. Or trigger a run against a specific file at any time via the API:
   ```bash
   curl -X POST http://localhost:8000/pipeline/run \
     -H "Content-Type: application/json" \
     -d '{"data_path": "/path/to/your_data.csv"}'
   ```
   (the dashboard sidebar exposes this as a "Data path override" field next
   to the **Run / Refresh pipeline** button)

Real customer data should not be committed to version control — this repo's
`.gitignore` excludes anything at `data/data.csv` by convention if you choose
to keep your working dataset under that name.

## API Reference

| Endpoint | Method | Description |
| --- | --- | --- |
| `/health` | GET | Liveness check |
| `/status` | GET | Pipeline readiness, data path, row counts |
| `/pipeline/run` | POST | (Re-)runs the pipeline; optional `{"data_path": ...}` override |
| `/data/quality` | GET | Cleaning-stage stats (missing values, duplicates, cancellations, anomalies) |
| `/metrics` | GET | Clustering evaluation metrics (silhouette, Calinski-Harabasz, Davies-Bouldin) |
| `/clusters/summary` | GET | Per-cluster size, percentage, and standardized centroid |
| `/clusters/pca` | GET | Per-customer PCA components + cluster label |
| `/clusters/features` | GET | Full per-customer feature table + cluster label |
| `/clusters/top-products` | GET | Best-selling products per cluster (`?cluster=N`) |
| `/recommendations` | GET | Paginated recommendations (`?cluster=N&limit=&offset=`) |
| `/recommendations/{customer_id}` | GET | Recommendations for a single customer |

## Dashboard

The Streamlit dashboard provides four views:

- **Data Overview** — raw vs. cleaned row counts and data-quality breakdown.
- **Cluster Visualization** — cluster size distribution, evaluation metrics,
  and a 3D PCA scatter plot of customer segments.
- **Cluster Profiles** — radar chart of standardized feature means per
  cluster, per-feature histograms, and top-selling products per segment.
- **Recommendations** — look up a customer's top-3 recommended products, or
  browse/filter the full recommendation table.

## Configuration

Key parameters live in `app/config.py` and can be tuned as needed:

| Setting | Default | Description |
| --- | --- | --- |
| `ISOLATION_FOREST_CONTAMINATION` | `0.05` | Expected proportion of outlier customers |
| `PCA_N_COMPONENTS` | `6` | Number of principal components retained |
| `N_CLUSTERS` | `3` | Number of K-Means clusters |
| `TOP_N_PRODUCTS_PER_CLUSTER` | `10` | Best-sellers considered per cluster |
| `TOP_N_RECOMMENDATIONS` | `3` | Recommendations generated per customer |

## Design Notes

A few deliberate deviations from the original notebook, made while porting it
into reusable, dataset-agnostic code:

- **Cluster labeling**: clusters are relabeled by descending size (cluster
  `0` = largest segment) rather than a hardcoded mapping tuned to one
  specific dataset, so labels stay meaningful on any input data.
- **Cancellation rate**: computed via an explicit merge on `CustomerID`
  rather than positional division, which only worked in the notebook because
  of coincidental row ordering.
- **Recommendation padding**: rows are padded with `null` when a cluster
  doesn't have enough not-yet-purchased best-sellers to fill all
  recommendation slots (mainly relevant for small datasets).
